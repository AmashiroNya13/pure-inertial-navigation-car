# 纯惯导软件

> 本文是本项目纯惯导软件的设计说明与工程经验记录。文中的频率、距离、阈值和参数用于说明当时的设计思路；实际默认值及可用范围应以当前源码和实车验证为准。

## 传感器

- **IMU**：负责航向偏移稳定。若航向歪斜，通常表现为路径整体旋转一个角度。
- **编码器**：负责横向误差锁定真实路径。若发生打滑，通常表现为平行路径但存在固定偏移。

偏移不止这两个因素，本文先聚焦于它们。

## 软件

### 1. IMU

IMU 获取角度通常有两种处理方式。

#### 1.1 角速度积分

主要由陀螺仪提供角速度，再根据某个时间戳完成积分。

1. **由主控提供时间戳**：会受到主控时间戳波动影响，而主控时间戳又受主控时序影响。因此应尽可能提高 IMU 数据处理优先级。这个思想同样适用于多数需要积分的场景，必须严肃考虑时序波动。
2. **由 IMU 提供时间戳**：理论上可能更准，但问题很多。最严重的是，这个时间戳并非 IMU 更新某条数据的时间戳，而是 IMU 自身当前时间戳，没有对数据点做标记；因此效果和主控时间戳相近，甚至可能更差。
3. **由 DMA 读取时获得时间戳**：这个时间戳较准确，实测可视为主控时间戳的上位推荐，能明显缓解时序不准问题，但实现仍有难度。

#### 1.2 IMU 自身四元数解算

由 IMU 自身完成独立四元数积分，输出 Game Rotation Vector 角，也就是向量角。该方式不必担心主控时序，也不会因 IMU 实时性要求侵蚀主控时序。

它仍有局限：难以进一步使用陷波等滤波算法，陀螺仪自身的静止修正算法精度有限，更新频率也较有限。滤波、静止修正和更新频率导致的问题在此不展开。

#### 1.3 本项目 IMU 与初始化现象

本项目使用 ST 的 LSM6 系列、带自解算四元数的版本。其自解算最高输出 480 Hz 角度数据，原始角速度和加速度最高输出 7000 Hz；此外还能读取温度、零偏修正数据和时间戳。

实测中，该 IMU 开启自解算 Game Rotation Vector 输出后的前 17 秒，数据会呈现“耐克状”弯钩，并可能形成永久性误差。因此上电后应禁止这 17 秒内的角度累计更新；期间并不要求车辆静止。

#### 1.4 零偏与外部干扰

IMU 数据通常包含零偏并会受到外部干扰。这里的外部干扰主要指负压振动和行进振动。

零偏通常由温漂、随机游走、电磁噪声和固定零偏构成：

- **温漂**可以通过恒温电路控制，但面对双 IMU、多 IMU、重量限制和布板限制，实现并不容易。一个思路是由主控通过 PWM 控制电阻的电流、电压以实现恒温；多 IMU 情况下 PWM 需求和复杂度都会增加。
- **随机游走**正负平均后通常不需要额外修正。
- **电磁噪声**个人观察中影响较大。这里主要隔离高频噪声，可使用马口铁、洋白铜、不锈钢，甚至铝合金进行多点接地隔离。项目中选择了约 0.15 mm 厚的洋白铜：不锈钢与马口铁款式较少，铝合金虽然更轻但难焊接、制作成本高，且担心焊接失败影响隔离效果。

固定零漂的处理思路是：关闭角度输出的自修正寄存器，把 IMU 静置在稳定桌面上，通过至少 409600 波特率的高速串口打印角度数据，确保环境没有异常振动，放置一整夜，再分析斜率以标定粗略零偏。

开机 17 秒后，使用加速度计、陀螺仪和编码器共同检测静止。静止时的加速度、角速度和编码器跳动数据可用于分析合理阈值。在连续共同静止的死区内，IMU 禁止角度更新，并在固定零偏粗略处理后做更细致的零偏处理。

为避免时间跨度过大导致修正不够实时，设计上每 5 秒解算并使用一次零偏。退出静止的阈值略小于进入阈值；采用计数退出机制，即运动状态 `+1`、非运动状态 `-0.5`。另外通过小数据窗口缓存，保证进入/退出判断过程中用于确认的帧也能按正确状态重新处理。目标是在上电 17 秒后，只要放下不动就进入静止状态，保持极低漂移并可实时修正；灵敏度达到点击鼠标或手放在桌上抖腿会被识别为运动，同时尽量避免误判。

外部干扰中，行进端因硅胶胎减振且相对稳定，影响可在一定程度上忽略。负压端固定在底板，高速旋转并与空气做功，抖动更大、频率更高、难抓取也难滤除。由于车况变化较大，基于模型的减振或陷波较难稳定标定，更适合从机械侧使用海绵减振、分板减振或减振柱等方案。

以上是作者对 IMU 软件的部分理解，请结合实际情况自行判断。

### 2. 编码器

本项目使用 SPI 通信的 14 位编码器，以 1920 Hz 通过 DMA 自主读取角度数据并计算差值，属于 M 法测速。相对 T 法，其高速性能更好；同时因时序准确，实际效果较好。

编码器算法本身没有特别复杂的计算。作者不建议为了抑制齿槽或齿轮效应带来的抖动而盲目增加低通滤波：这类抖动很难被有效滤除，低通滤波反而引入相位滞后。去掉不必要滤波后，响应可能更快、修正更及时、实际波动也可能更小。该结论应以具体硬件数据验证。

## 控制算法

电调侧采用六步换向和过零校正。主控侧输出 PWM，使用双串 PID：480 Hz 的双自由度角度环，连接 1920 Hz 的前馈速度环。

### 1. 双自由度角度环

惯导路径控制通过转向前瞻目标的 `x/y` 坐标与自身 `x/y` 坐标计算目标角度差，再送入角度环。角度环为作者实现的“双自由度 PD”：经典 PD 加微分先行 D，再用二自由度约束对两个 D 做加权调节。

设计来源于两种观察：

- 使用经典 PD 时，过弯通过率高，但摆动较大，路径不够准确。
- 使用微分先行 PD 时，贴路径效果很好，但偶发转弯突然失控，且失控位置可能高度一致。

二者融合后，在 PD 固定且不需要精确重新调参的情况下，可以主要调整自由度：自由度较低时，过弯成功率更高，但会带来更平滑、略超调且不再紧贴路径的感觉；自由度较高时，路径跟随更紧，但会降低过弯成功率。实测中较高自由度可达到较好的综合效果。角度环不建议额外使用前馈。

### 2. 速度环与前馈

角度环计算出的相反速度误差分别送到左右轮速度环。速度环由前馈加 PI 构成，速度目标值需经过加速度限制以限制速度阶跃斜率。这是速度规划的前置条件，可从源头降低打滑、起步翘头和停车翘尾风险。

加减速限制是最大限制。具体加减速能力应来自实车标定：在无角度环的闭环速度环直线测试中，于多个速度点测得稳定 PWM，形成前馈表；目标区间之间进行线性插值，即可得到相对准确的全速度段前馈。作者记录中，单 PI 响应约 40 ms、单前馈约 30 ms，二者结合可降至约 17 ms 或更低。最后通过 PWM tick 斜率控制输出左右轮 PWM，主控只需限制明显错误输出，电调侧保留更严格的限制。

### 3. 前瞻解耦

速度前瞻和角度前瞻分别影响基础目标速度和转向角度。因此，“角度环串速度环”在本项目架构中并非传统串级：传统串级中上一级输出全额管控下一级；这里角度环输出的是差速，速度环将差速叠加到基础目标速度形成最终目标速度。

将两类前瞻分开可解耦基础目标速度和角度控制。若解耦不到位，速度规划可能成为一厢情愿：作者曾在固定 3.5 m/s 与最高直道规划 3.5 m/s 的测试中发现，虽然后者会因摩擦力规划而在弯道降至约 2.5 m/s，直道仍可能比原本更快，而弯道反而无法通过。

后续将速度前瞻设为约 1 cm、转向前瞻约 21 cm 后，弯道通过率明显提高。速度前瞻调至 2 cm 时，在相同速度下出现约 5 cm 的严重横向打滑；调小后仍可能打滑但幅度较小。可见在较大加减速限制下，该阈值较严格。因此应优先确保速度与角度控制真正解耦，再讨论速度规划效果。

## 惯导路径与修正

### 1. 路径表示和导入

作者认为，仅计算和记录 `x/y` 坐标是较优的惯导路径表示；单纯曲率或路程记录缺少点间框架约束，难以纠正，只能反复复现。项目以约 5 mm 间隔记录一个 `x/y` 点到 Flash。

转向目标角由路径 `x/y` 坐标与实时自身位置计算，频率与转向环一致，为 480 Hz。高速时必须注意离散位置记录：转弯曲率变化应连续，否则会在某些帧引入运行毛刺和 `x/y` 错位。

因此路径使用 Web 工具导入并保存到 Flash，以便人为控制路径、平滑路径和降低曲率阶跃。若电调能接受更高的速度环频率，例如 2880 Hz，还可以固定基础速度并依据编码器单独改变路程，进一步提高操控能力；建议速度环频率选用基础频率的整数倍，优先为 2 的倍数。

### 2. IMU 与编码器交叉修正

惯导修正要求 IMU 和编码器分别维护一套角度。编码器角度依赖轮距计算，但实测中轮距随速度和转弯半径变化，难以细致标定，因此不建议过度追求单一精确轮距。

获得两套角度后，应持续比对最近窗口内的角度差变化。一旦评估差值过大，例如重合率低于约 84%，可把 IMU 角度视为编码器角度，并通过轮距反推编码器路程，以修正总里程。

Flash 读取必须使用缓冲区并进行无缝切换；否则不仅无法实时运行，也可能卡死并造成撞车风险。

### 3. 偏移来源与路径规划

惯导偏移可能来自：

1. 航向角漂移。
2. 坐标记录离散或遗漏。
3. 编码器打滑。
4. 路径本身的问题，即“以什么路径为复现基准”。

路径规划建议通过 Web 导入 5 mm 离散节点。该方法不仅支持提前切弯，也可以利用摩擦圆算法为每个点给出规划速度和切弯半径，对精准惯导控制有帮助；还可扩展禁修区等功能。

### 4. 当前前瞻设计与后续设想

作者记录的常态前瞻为：约 1 cm 速度前瞻、约 21 cm 转向前瞻，以及基于转向前瞻的约 3 cm 切线前瞻。车辆自身坐标超过上一个弯道的出弯点后会进入直线状态；此时前瞻直接盯住下一个弯道的入弯点，以获得更强的直道抗扰动效果。

后续可考虑为每个弯道建立标定：上位机将转弯处理为恒定转弯半径，摩擦圆算法得到相对稳定的弯道速度，每个导入点带规划速度。在恒定转弯半径、恒定过弯速度和恒定基础速度下跑一趟弯道，即可观察弯中横向偏差，并通过增减当前转向前瞻距离形成“速度-最佳前瞻距离”表。这样直道可按下一个弯道提前预瞄，弯道则按速度选择更合适的前瞻距离，使控制进一步精细化。
